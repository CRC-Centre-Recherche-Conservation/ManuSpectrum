# ManuSpectrum 1.0.3 release notes

## Fixes

### Monitoring

- `ContainerMemoryNearLimit` no longer fires on the page cache (#351). It read the working set of `docker stats`, which
  still counts the active page cache; the kernel drops that cache when a container reaches its limit, so Cantaloupe,
  which reads large images and writes its derivative cache, sat near 100 % of its limit without any risk. The alert
  now reads the new `manuspectrum_container_memory_unreclaimable_bytes` (`anon` plus `shmem` of the cgroup v2
  `memory.stat`), and the working set only for a container whose `memory.stat` the collector cannot read.
  `WebMemoryNearLimit` is unchanged.
- The Infrastructure dashboard shows both series in « Memory used by container » (the working set dashed, marked
  « with page cache »), and « Share of the memory limit » shows what the alert reads.
- The `ContainerMemoryNearLimit` runbook gives the `memory.events` and `memory.stat` check that tells a kernel
  reclaim from a real shortage.

### Image server

- Cantaloupe now purges its expired derivatives (`CANTALOUPE_CACHE_SERVER_WORKER_ENABLED`, once a day). The image
  default leaves the cache worker off, so tiles past their 30-day lifetime were never deleted and the cache volume
  (`ms_cantaloupe_cache`) only grew.

### Annotation zones

- A zone drawn in the Arches viewer is now placed where it was drawn on every image, in the Data Lab, in the IIIF
  annotations (`/iiif/v3|v2/…`, the content states, the data package) and in the search thumbnails. Arches stores a
  zone in the units of the image layer its viewer draws, and one unit is 8, 16, 32 or 64 pixels depending on the
  image's size and on the tile width its `info.json` declares; the project counted 32 for every image, so a zone was
  right only on an image between 4 097 and 8 192 pixels served in 256-pixel tiles. Images served by the platform's
  own image server (512-pixel tiles) showed their zones at twice the distance from the top-left corner, squeezed
  against the page edges.
- The server reads the `info.json` of an image that carries a zone (kept 7 days, `IIIF_IMAGE_INFO_*` in
  `settings.py`). When it cannot (a host that refuses server-side requests), the unit is assumed from the canvas size
  at 256-pixel tiles, or at the tile width `IIIF_IMAGE_TILE_HINTS` gives for the host; the Data Lab still shows the
  zone where Arches draws it, and the document payload says the unit is assumed (`canvases[].zoneUnit.read`).
- A whole-page zone written by the Biblissima import now covers the page in the units of its image. Pages imported
  earlier on an image whose unit is not 32 keep the zone they were given: redraw it in the Arches viewer. On a host
  that refuses server-side reads, the zone is written with an assumed unit (256-pixel tiles unless
  `IIIF_IMAGE_TILE_HINTS` names the host).
- The conversion holds for the tiling served when a zone was drawn: re-encoding an image, or changing Cantaloupe's
  tile size, moves the zones already drawn on it.

## Upgrading

- Install the release with `sudo manuspectrum-update` (`deploy/ADMIN.md`, « Updating the application »). The
  collector picks up the new series at its next run (30 s).
- Prometheus reads its rules when it starts: restart it once the update is done, as the service account, so that it
  loads the changed rule.

  ```bash
  docker restart "$(docker ps -qf label=com.docker.compose.service=prometheus)"
  ```
