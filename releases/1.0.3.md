# ManuSpectrum 1.0.3 release notes

## Fixes

### Monitoring

- `ContainerMemoryNearLimit` no longer fires on the page cache (#351). It read the working set of `docker stats`, which
  still counts the active page cache; the kernel drops that cache when a container reaches its limit, so Cantaloupe,
  which reads large images and writes its derivative cache, sat near 100 % of its limit without any risk. The alert
  now reads the new `manuspectrum_container_memory_unreclaimable_bytes` (`anon` plus `shmem` of the cgroup v2
  `memory.stat`), and the working set only for a container whose `memory.stat` the collector cannot read.
  `WebMemoryNearLimit` is unchanged.
- The Infrastructure dashboard shows both series in « Memory used by container » (the working set dashed, marked
  « with page cache »), and « Share of the memory limit » shows what the alert reads.
- The `ContainerMemoryNearLimit` runbook gives the `memory.events` and `memory.stat` check that tells a kernel
  reclaim from a real shortage.

- Containers could swap after a systemd reload (#371). `memswap_limit` made Docker write `memory.swap.max=0` to each
  container's cgroup, but runc does not pass `MemorySwapMax` to systemd when the swap allowance is 0
  (opencontainers/cgroups#74), so the container's scope unit kept `MemorySwapMax=infinity` and the next
  `systemctl daemon-reload` (an apt upgrade, Ansible) reset the file to `max`: Cantaloupe held 575 MiB in swap. The
  Ansible `host` role now installs `/etc/systemd/system/docker-.scope.d/10-manuspectrum-no-swap.conf`
  (`MemorySwapMax=0` for every Docker scope) and reloads systemd, which applies it to the running containers without
  restarting Docker. Remove it once runc ships opencontainers/cgroups#78.
- The collector exports `manuspectrum_container_memory_swap_bytes` and `manuspectrum_container_swap_allowed`, and two
  warnings read them: `ContainerSwapAllowed` (a container may swap, 15 minutes) and `ContainerSwapping` (a container
  holds pages in swap, 30 minutes), with runbooks. The `SwapInUse` runbook explains how to find who holds the swap,
  and the acceptance checklist reads `memory.swap.max` before and after a `daemon-reload`.

### Image server

- Cantaloupe now purges its expired derivatives (`CANTALOUPE_CACHE_SERVER_WORKER_ENABLED`, once a day). The image
  default leaves the cache worker off, so tiles past their 30-day lifetime were never deleted and the cache volume
  (`ms_cantaloupe_cache`) only grew.

## Upgrading

- Re-run the Ansible `host` role from the administrator's laptop (`ansible-playbook -i inventories/<host> site.yml
  --tags host --ask-become-pass`, `deploy/ansible/README.md`): it installs the no-swap drop-in and reloads systemd.
  Docker and the containers are not restarted. Check `memory.swap.max` is `0` for every container (`ACCEPTANCE.md` § 2.5).
- Then restart Cantaloupe off-peak so the pages it already holds in swap come back (the limit stops new swapping, not
  the old pages):

  ```bash
  docker restart "$(docker ps -qf label=com.docker.compose.service=cantaloupe)"
  ```
- Install the release with `sudo manuspectrum-update` (`deploy/ADMIN.md`, « Updating the application »). The
  collector picks up the new series at its next run (30 s).
- Prometheus reads its rules when it starts: restart it once the update is done, as the service account, so that it
  loads the changed rule.

  ```bash
  docker restart "$(docker ps -qf label=com.docker.compose.service=prometheus)"
  ```
