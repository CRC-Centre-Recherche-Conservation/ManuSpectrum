# ManuSpectrum 1.0.4 release notes

ManuSpectrum 1.0.4 keeps the server logs for one year, as the CNRS security review of the platform requires: the
nginx access and error logs, the logs of every container, the systemd journal and the system's text logs, with a
daily archive of the closed logs into the hosting provider's TSM. It also adds the IRHT to the partner logos and
states on the legal notice how generative AI was used to build the platform. No migration, no data step; the update
needs the Ansible playbook first (« Upgrading ») and recreates every container.

## Logs

- The nginx access and error logs are rotated daily and kept 365 days on the host (was 30 days). They carry the
  client IP address, unaltered.
- The containers log to the systemd journal (Docker `journald` driver, tagged with the container name) instead of
  `json-file` files of 10 MB × 5, which held a few days at most. `docker logs` and `make -C deploy logs` read them as
  before; `journalctl CONTAINER_NAME=<name>` reads them too.
- The systemd journal keeps one year (`MaxRetentionSec=1year`, was 3 months), one file per day (up to 2000 files),
  at most 12 GB (was 500 MB). Measured on the production host, the journal and the containers write about 15 MB a day.
- The system's text logs keep about one year: `auth.log`, `syslog`, `kern.log`, `ufw.log` and `fail2ban.log` 52 weeks
  (was 4), `wtmp` and `btmp` 12 months (was 1). A rule missing from the host is skipped.
- A daily timer (`manuspectrum-log-archive.timer`, 07:30, root) archives each closed log once into TSM with
  `dsmc archive` (365 days on the TSM server): the rotated nginx logs, the rotated `*.gz` under `/var/log` and the
  archived journal files. Ansible installs the script root-owned under `/usr/local/lib/manuspectrum/log-archive/`;
  the unit never runs the checkout. Where `dsmc` is not installed the run archives nothing and says so. A new warning,
  `LogArchiveStale`, fires after two days without a successful run (`deploy/runbooks/backup.md`).
- The privacy page states the new retention of the access and error logs (one year, then deleted) and lists the
  application log (sign-ins, failed sign-ins and lockouts, with user name, IP address and browser), kept one year.
  It also lists the server system logs (mails sent by the platform, administrators' connections) and states that the
  host's backup copies of the logs are deleted at most two months after the year.
- On a host backed up by the hosting provider's TSM, the `host` role adds `/var/log` to the backup domain
  (`/var/spool/tsm/etc/dsm.sys`), and fixes the nightly job (`/etc/cron.daily/tsm`): it named a server missing from
  `dsm.sys` (`ANS1217E`, nothing backed up) and ran without a UTF-8 locale (`ANS4042E` on every file name with an
  accent). The job now uses the server of `dsm.opt` and `C.UTF-8`; the archive run uses `C.UTF-8` too. Nothing
  happens on a host without these files.
- `deploy/BACKUP.md` « Logs » describes where each log is kept and what TSM holds.

## Public pages

- The IRHT (Institut de recherche et d'histoire des textes) joins the partner logos, between CRC and ANR, on the
  homepage and the Team page (#402).
- The legal notice gains a « Use of generative AI » section: generative AI tools helped write part of the source code
  and translate the interface and vocabularies between French and English, the team reviewed this work, and the
  records, images and analysis files are not AI-generated. The European Commission's AI icon heads the section, and
  the footer of every public page links to it with the same icon (#403).

## Upgrading

- Ansible first: the `host` role changed (journald drop-in, rsyslog rotation) and so did the nginx logrotate rule, so
  the update refuses until the playbook has run from a laptop checkout at `v1.0.4` (`deploy/ADMIN.md`, « When the
  update refuses because Ansible must run first »). It restarts journald, fixes the TSM files and installs the log
  archive timer; Docker and the containers are not restarted. `sudo manuspectrum-update --status` keeps showing
  `needs_ansible=1` until the next hourly watch run (`sudo systemctl start manuspectrum-watch.service` refreshes it at
  once); the update checks the host itself, so it can be started right after Ansible.
- After Ansible, on a host backed up by TSM: `sudo grep -n -iE 'domain|var/log' /var/spool/tsm/etc/dsm.sys` shows
  `/var/log` in the `DOMAIN` and an active `VirtualMountpoint /var/log`; the day after, `sudo grep -a -E
  'ANS[0-9]{4}E|failed' /var/spool/tsm/log/dsmc.incremental.local.log` shows no error and `objects failed: 0`, and
  `sudo dsmc query filespace` lists `/var/log` with that morning's date.
- Then install the release with `sudo manuspectrum-update` (`deploy/ADMIN.md`, « Updating the application »). The
  logging driver of every service changes, so the update recreates every container: plan a longer interruption than
  for 1.0.3 (about 50 s of downtime on the rehearsal VM, against 40 s).
- The update recreates the containers, which deletes their `json-file` logs. To keep them, save them just before the
  update, from the admin account (it is not in the `docker` group, hence `sudo docker`); the next archive run takes
  them into TSM (delete that directory one year later):

  ```bash
  sudo mkdir -p /var/log/manuspectrum-before-1.0.4
  for c in $(sudo docker ps -q --filter label=com.docker.compose.project=manuspectrum); do
    n="$(sudo docker inspect -f '{{.Name}}' "$c" | tr -d /)"
    sudo docker logs --timestamps "$c" 2>&1 | gzip | sudo tee "/var/log/manuspectrum-before-1.0.4/$n.log.gz" >/dev/null
  done
  ```
