# ManuSpectrum 1.0.4 release notes

ManuSpectrum 1.0.4 keeps the server logs for one year, as the CNRS security review of the platform requires: the
nginx access and error logs, the logs of every container, the systemd journal and the system's text logs, with a
daily archive of the closed logs into the hosting provider's TSM. No migration, no data step; the update needs the
Ansible playbook first (« Upgrading ») and recreates every container.

## Logs

- The nginx access and error logs are rotated daily and kept 365 days on the host (was 30 days). They carry the
  client IP address, unaltered.
- The containers log to the systemd journal (Docker `journald` driver, tagged with the container name) instead of
  `json-file` files of 10 MB × 5, which held a few days at most. `docker logs` and `make -C deploy logs` read them as
  before; `journalctl CONTAINER_NAME=<name>` reads them too.
- The systemd journal keeps one year (`MaxRetentionSec=1year`, was 3 months), one file per day, at most 12 GB (was
  500 MB). Measured on the production host, the journal and the containers write about 15 MB a day.
- The system's text logs (`/var/log/auth.log`, `syslog`, `kern.log`…) keep 52 weeks (was the Ubuntu default of 4).
- A daily timer (`manuspectrum-log-archive.timer`, 07:30, root) archives each closed log once into TSM with
  `dsmc archive` (365 days on the TSM server): the rotated nginx logs, the rotated `*.gz` under `/var/log` and the
  archived journal files. Ansible installs the script root-owned under `/usr/local/lib/manuspectrum/log-archive/`;
  the unit never runs the checkout. Where `dsmc` is not installed the run archives nothing and says so. A new warning,
  `LogArchiveStale`, fires after two days without a successful run (`deploy/runbooks/backup.md`).
- The privacy page states the new retention of the access and error logs (one year, then deleted) and lists the
  application log (sign-ins, failed sign-ins and lockouts, with user name, IP address and browser), kept one year.
- `deploy/BACKUP.md` « Logs » describes where each log is kept and what TSM holds.

## Upgrading

- Ansible first: the `host` role changed (journald drop-in, rsyslog rotation) and so did the nginx logrotate rule, so
  the update refuses until the playbook has run from a laptop checkout at `v1.0.4` (`deploy/ADMIN.md`, « When the
  update refuses because Ansible must run first »). It restarts journald and installs the log archive timer; Docker
  and the containers are not restarted. Then check that `sudo manuspectrum-update --status` shows `needs_ansible=0`.
- On a host backed up by TSM, add `/var/log` to the `DOMAIN` line of `/var/spool/tsm/etc/dsm.sys` and uncomment its
  `VirtualMountpoint` (the provider's file, edited by hand), so the daily TSM backup covers the system logs too.
- Then install the release with `sudo manuspectrum-update` (`deploy/ADMIN.md`, « Updating the application »). The
  logging driver of every service changes, so the update recreates every container: plan a longer interruption than
  for 1.0.3.
- The container logs written before the update stay in their `json-file` files until Docker removes the old
  containers; they are not moved to the journal.
