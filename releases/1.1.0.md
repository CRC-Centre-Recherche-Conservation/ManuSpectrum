# ManuSpectrum 1.1.0 release notes

ManuSpectrum 1.1.0 is a feature release of the Data Lab.

## Changes

- Data Lab: the title of a Selection item opens it in its document, on its page, with its zone drawn and its card
  (analysis or identified material) open (#339). A Ctrl, Cmd, Shift or middle click opens it in a new tab instead. The
  browser's Back returns to where the click came from, and closing the card leaves the visitor on the same page. A row
  says when its analysis is not located on a page, and a material row shows its document. « Open in the document »
  in Compare's focus legend and « Open the analysis » in the « Without visualisation » window behave the same way; the latter
  no longer opens a new tab. A document opened from Compare offers « Back to Compare ».
- IIIF: every Document and Component has its own manifest, `/iiif/v3/manifest/<uuid>` (Presentation 3) and
  `/iiif/v2/manifest/<uuid>` (Presentation 2.1), built from the same facts as its annotation collection: the pages
  that carry an analysis or an identified material, each referencing its annotation pages, and a header that says
  what the document is (the fields of its summary), what was analysed (techniques, projects, dates, chemical imaging),
  who publishes it and where to download the data. It is filtered for its reader like the annotation pages, and
  `/iiif/v3/explorer-manifest?document=<uuid>` now answers a permanent redirect to it.
- IIIF: the Data Lab manifests of a selection or a project carry the same header, and their label counts the analyses
  and pages (« Selection of 12 analyses on 1 page of … »). Imaging manifests are referenced by their address in the
  header instead of having their layer canvases copied into the manifest.

## Arches 8.2

ManuSpectrum moves from Arches 8.1.6 to Arches 8.2 (Django 6.1). What the operator does:

### Before the update

- **Python and Node.** Arches 8.2 needs Python 3.12 or later and Node 24. The application image already runs Python
  3.13 and Node 24; nothing to do on the host.
- **PostgreSQL 16 or later.** Production runs 17; nothing to do.
- **`standard_conforming_strings` back to PostgreSQL's default (`on`).** Compose no longer starts PostgreSQL with
  `off`, which Arches' old install scripts set: Arches 8.2's own SQL needs `on`. The update recreates the
  `postgres` container; stored data is unchanged.
- **Elasticsearch 9.** Compose now pins `elasticsearch:9.5.5` (the client of Arches 8.2 is `elasticsearch>=9.5.1`).
  The `ms_es_data` volume of 8.19 is opened by 9; the index is rebuilt anyway (below). The update engine's automatic
  rollback puts the 8.19 image back, and Elasticsearch 8 refuses a data directory that 9 has opened: after a rollback,
  remove the `ms_es_data` volume and run `es reindex_database` (the index is derived data, never backed up).
- **Migration window.** Migration 13002 adds `id`, `createdtime` and `last_updated` to `tiles` and `resource_instances`
  and locks both tables while it runs: plan the window and raise `RELEASE_READY_WAIT_SECONDS` (maximum 1800) before
  the update, as for any long migration.

### After the update

- **Rebuild the search index:** `make -C deploy manage ARGS="es reindex_database"`. Relationship keys and node
  aliases change names, which changes the index mapping.
- **Node aliases.** Aliases ending in an underscore are renamed by the migrations (33 in our graphs); the relationship
  keys stored in tile data are renamed with them. Saved links and exports that name an old alias need the new one.
- **Rich text.** Arches 8.2 replaces CKEditor 4 with its own editor (Tiptap). Stored rich text, and how reports
  show it, is unchanged until a tile is saved again; on that save the editor drops what it does not support (CKEditor
  styles such as `marker`, `big` or `small`, table borders and cell styles, inline image size and float, text alignment
  and indentation, anchors, page breaks). Spell checking is the browser's. Ask editors to review a rich-text field
  after editing it. CKEditor's calls to `cke4.ckeditor.com` and WebSpellChecker are gone, and so is their entry on
  the privacy page.
- **Package.** Nothing to do on an existing host: an update never loads `pkg/` (only `make init` does, on a new
  database). Do not re-export `pkg/` from an 8.2 database yet: Arches 8.2's importer refuses the empty default
  values its 12587 migration moves into the node config (#388).

### Before tagging 1.1.0 (release manager)

- **Check that production matches the package, read-only.** Before merging the package PR, on the production
  host (still on 1.0.x, Arches 8.1.6), compare the database with the inventory of the package's `main`:

  ```bash
  # from the application checkout on the host; MEDIA_HOST_DIR as set in deploy/compose/.env
  MEDIA_HOST_DIR=$(grep '^MEDIA_HOST_DIR=' deploy/compose/.env | cut -d= -f2-)
  curl -fsSL https://raw.githubusercontent.com/CRC-Centre-Recherche-Conservation/manuspectrum-pkg/main/expected-inventory.json \
    -o "$MEDIA_HOST_DIR/pkg-inventory-check.json"
  make -C deploy manage ARGS="check_pkg_inventory /srv/media/pkg-inventory-check.json"
  rm "$MEDIA_HOST_DIR/pkg-inventory-check.json"
  ```

  `check_pkg_inventory` only reads. No difference: production and the package agree. A difference (a list or
  graph changed in production by script, not exported): the package is behind production; export the package
  from production in its own package PR first, before #18 and the 1.1.0 update.
- **Rehearse the update on the staging test database** (a recent production copy), before the release candidate:
  the Arches 8.2 migrations on real data and their duration (13002 locks `tiles` and `resource_instances`),
  `es reindex_database` on Elasticsearch 9, the rollback path, and in a browser the annotation counts of a large
  manuscript (Grenoble Ms. 76 Rés., 772 canvases), the annotation widget and the manifest manager.
- **Merge the package PR once `dev-1.1.0` is in `dev`.** CRC-Centre-Recherche-Conservation/manuspectrum-pkg#18
  (inventory: 6 functions, load test on Arches 8.2): merge the package's `main` into it if it moved, re-run its load
  test (it loads into `dev` by default; before `dev-1.1.0` is merged, dispatch it with `app_ref: dev-1.1.0`), then
  merge it into the package's `main` with a merge commit (never squash or rebase).
- **Then update the submodule, before the release candidate.** Point `pkg` in `dev` at that merge commit on the package's `main`
  (`git -C pkg fetch && git -C pkg switch --detach origin/main`, commit the new pointer). The pinned commit must be
  reachable from the package's `main`: today the branch points at the PR's head, which `make -C deploy init` and
  the image job load but which a squash would orphan.

## Features

### Annotation zones

- A zone of an annotation now carries a stamp of the image frame it was drawn in: `msUnit` (image pixels per stored
  unit, a power of two), `msImageWidth`, `msImageHeight` and `msFrame` in the zone's properties. `msFrame` is
  `browser`, `read` or `import-legacy` when the frame was measured, and `estimated` when it was assumed. A zone with a
  measured frame keeps its exact place whatever the image host does later (re-encoding, another tile size), in the
  Data Lab, the IIIF annotations and the data package, and costs no request to the image host; a search thumbnail
  keeps it while the image keeps its size (its region is cut in the stamped image's pixels).
  An `estimated` zone still follows the live image in the Data Lab, and Arches' own back-office viewer keeps drawing
  every zone in the live layer: old zones shift there after a re-tile until a rebase (planned).
- Zones on a host that refuses server-side reads (Gallica) are stamped `estimated` (256-pixel tiles unless
  `IIIF_IMAGE_TILE_HINTS` names the host); the Data Lab draws them where Arches draws them. This needs the manifest
  registered, so the canvas size is known; otherwise `annotation_frames check` lists the zone and it stays unstamped.
- A whole-page zone written by an earlier Biblissima import is recognised and stamped `import-legacy`.
- The gauge `manuspectrum_annotation_zones{state}` counts the zones per state.
- The stamps are pinned to Arches' viewer, leaflet-iiif and Leaflet by `tests/test_arches_pins.py`: it fails when what
  the stamps rely on changes.

## Upgrading

- Install the release with `sudo manuspectrum-update` (`deploy/ADMIN.md`, « Updating the application »).
- Run the annotation zone commands below after the Arches 8.2 steps and before the index rebuild: one
  `es reindex_database` then covers both.
- Zones saved before the release are stamped by a command, never at read time (`deploy/ADMIN.md`, « Annotation zone
  frames »). Count them, stamp them with a journal, then reindex so the stamps reach Elasticsearch:

  ```bash
  make -C deploy manage ARGS="annotation_frames check"
  make -C deploy manage ARGS="annotation_frames stamp --apply --journal /srv/media/annotation-frames-YYYYMMDD.jsonl"
  make -C deploy manage ARGS="es reindex_database"
  ```

  `annotation_frames stamp` without `--apply` is a dry run. To undo, run
  `annotation_frames unstamp --journal PATH` (dry run, then `--apply`) and reindex; a zone edited since is left alone.
  Run `annotation_frames check` after `stamp --apply`; if zones remain unstamped because a host was unavailable, run `stamp --apply` again later with a new journal.
- After any ETL or package load that brings zones, run the three commands above again (with a new journal file).
