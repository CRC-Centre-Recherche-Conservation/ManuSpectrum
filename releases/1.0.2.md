# ManuSpectrum 1.0.2 release notes

ManuSpectrum 1.0.2 is a security release: Arches 8.1.6 and a security update of the image, fixes found since the
opening of the site, and dependency updates. The data package changes one widget, 22 field defaults and the URI of 325 list
items, and adds three techniques (manuspectrum-pkg#11, #12, #13, #14); the graphs keep their publication, so existing
resources stay editable.

## Security

- **Arches 8.1.6** fixes four published Arches advisories that affect 8.1.5:
  - [GHSA-v8fw-q2g9-8j47](https://github.com/archesproject/arches/security/advisories/GHSA-v8fw-q2g9-8j47) (high):
    unauthenticated deletion of a controlled-vocabulary value (`/conceptvalue/`); it now requires the RDM
    Administrator group.
  - [GHSA-5r8g-pww9-vrcw](https://github.com/archesproject/arches/security/advisories/GHSA-5r8g-pww9-vrcw) (high):
    unauthenticated graph publication endpoints (publish, revert, restore, update published graphs); they now require
    the Graph Editor group.
  - [GHSA-8wfm-5r62-xfw2](https://github.com/archesproject/arches/security/advisories/GHSA-8wfm-5r62-xfw2) (medium):
    any signed-in user could create, change or delete resource relationships; it now requires edit permission on the
    resource.
  - [GHSA-2cjh-9m7p-g9mj](https://github.com/archesproject/arches/security/advisories/GHSA-2cjh-9m7p-g9mj) (medium):
    unauthenticated reset of a two-factor secret. ManuSpectrum was not exposed: nginx already refuses that route, and
    two-factor enrolment and reset are project pages.

  Arches 8.1.6 also makes a Resource Reviewer's deletion respect the resource's own permissions and its lifecycle
  state (archesproject/arches#13035).
- **oauthlib 4.0.1** (CVE-2026-49272, high): a transitive dependency of django-oauth-toolkit, found by the weekly
  scan of the production image.
- **No HTML page under `/static/`**: the npm packages ship sample, test and documentation pages, among them CKEditor 4
  samples with a known cross-site scripting flaw. The image publishes no `.html` or `.htm` static file, and its build
  fails if one gets through. Nothing the site loads is such a file.

## Fixes

- A manifest URL entered in a manifest field (Document « Facsimiles », Analysis « Chemical/physical imaging ») is
  saved and its manifest imported: the field used to save an empty value, so no remote manifest reached the database.
- Account activation and password reset links clicked from a webmail no longer end on « invalid link »: a valid link
  opens a « Continue » page instead of a redirect that lost the session cookie.
- A downloaded file keeps its stored name (an instrument file, a CSV, an export): it used to be saved under its
  identifier, without extension.
- Search thumbnails: a resource without a thumbnail no longer shows a broken image; a Component zone drawn as a point
  gets its thumbnail; a zone drawn outside its image is skipped for the next one; the image is asked at thumbnail size
  instead of full resolution; a thumbnail that failed (a library server refusing the site, such as Gallica) is not
  asked again for 5 minutes (`SEARCH_THUMBNAIL_MISS_TTL`); a fetched image is cached by its upstream address for 7 days
  (`SEARCH_THUMBNAIL_CACHE_TTL`), so a redrawn zone or a new manifest is fetched again and nothing else is; a tall
  thumbnail no longer stretches its row.
- The core map popup of a Place shows its text without HTML markup.
- The home page logo uses Cormorant Garamond on every system (it fell back to Georgia on Windows and macOS).
- File-list uploads with several files in one card (arches-vue-components 2.0.3, aligned with the Python package).
- Under `/fr/`, the data-entry cards show their French names, help texts and widget labels again. Arches 8.1 writes
  the active language's texts into every language of a graph publication during `i18n synclanguages`, `load_package`
  and « Update published graphs »; the new command `republish_graph_translations` rewrites them from the graph tables,
  in the same publication, and `init` runs it.
- The Component field « Iconographic representation » uses the Biblissima concept autocomplete instead of a plain URL
  field. Existing values are kept.
- Under `/fr/`, 22 pre-filled list fields (type of a name « termes préférentiels », source « PeriodO », dimension type
  « count ») showed « Unlabeled Item »: their defaults carried the English label only. They now carry every label of
  their list item, as a value picked from the list does.
- On reports, a Frollo technique (FORS, …) linked to a wrong address such as `/fr/report/61296`: the 325 items of the two
  Frollo lists stored their bare Opentheso id as URI. They now carry the concept's ARK
  (`https://ark.notre-dame.science/ark:/35572/…`), in the lists and in the resources that cite them.

- A manifest field holding a manifest imported from another institution can be saved again: the save used to fail
  with « Unable to save ».
- Mirador and other viewers on another site can open the stored manifests the IIIF output names (imaging layers, a
  Document's source manifest): the output names them at the language-neutral `/iiif/manifest/<uuid>`, served with the
  IIIF CORS headers and the read rules of the other IIIF routes. A manifest field accepts that URL as the stored
  manifest it names.
- A manifest field holding an imported manifest shows its label and its publisher's URL in search results and exports
  (it showed `/manifest/<uuid>`).
- The Explorer names a stored manifest at `/iiif/manifest/<uuid>` too (a Document's manifest, the imaging download
  link), so the link opens in an external viewer from another site.

## Changes

- The technique list (Frollo TAPAC) gains « X-ray fluorescence imaging » (« Imagerie de fluorescence X ») under « X-ray
  fluorescence », with two narrower terms: « macro X-ray fluorescence imaging » (MA-XRF) and « micro X-ray fluorescence
  imaging » (µXRF mapping). Frollo has no imaging term; the items link PaNET (`PaNET01288`) and CHMO (`CHMO_0002311`),
  and MA-XRF, which no vocabulary names, keeps a ManuSpectrum URI. « Microfluorescence X » stays for point analysis.
  Files of an analysis tagged with one of these get no automatic XY configuration: choose « XRF » in the file's
  configuration.
- A remote IIIF manifest used by a saved annotation is registered in the manifest list as soon as the annotation is
  saved, so the Arches viewer and the Image Service Manager offer it by its label on the next record. A manifest is
  never registered just by being viewed, and a refused download (for example Gallica, which blocks servers) leaves the
  annotation saved and is logged. `manage.py register_manifests [--apply]` registers the manifests of existing
  annotations and of bulk imports.
- A manifest imported from another institution is served at `/iiif/manifest/<uuid>` under that URL as its `id`, with
  its publisher's URL in `seeAlso`; it is still read from the copy stored at import, never fetched again. The Explorer
  links a Document to its publisher's manifest, and the data package cites each Document's source manifest in its
  README and RO-Crate (`subjectOf`).

## Deployment kit

- Google Search Console: a `GOOGLE_SITE_VERIFICATION` setting (empty by default) prints the `<meta
  name="google-site-verification">` tag of the « HTML tag » method in the head of the public pages; nothing is loaded
  from Google (`deploy/ADMIN.md` « Google Search Console »).
- Grafana's memory limit is 1536 MB in production (constant disk reads at the former limit).
- Ansible verify mode accepts the SSH rate limit as `ufw status verbose` prints it for the `OpenSSH` profile.
- New guides: `deploy/DEPLOY.md` (rebuild from zero, rollback, annual maintenance) and `deploy/INCIDENT.md`
  (decision tree); corrections from the first installation in `ADMIN.md`, `RELEASES.md` and `OBSERVABILITY.md`.

## Dependencies

Arches 8.1.6 (no migration), arches-querysets 1.2.0 (its concept and resource instance caches are per-process memory
caches, as upstream ships them), bibtexparser 2.1.0, papaparse 5.7.0, plotly.js-cartesian-dist 4.1.2,
@primeuix/themes 3.1.0 (public theme only; Arches keeps its own copy), primelocale 2.6.2, es-toolkit 1.53.0.

Development tools only (not in the image): arches-dev-dependencies 8.1.6 (vitest 4.1.12, TypeScript 5.9.3, which the
project now follows), black 26.10.1, django-silk 5.6.0. A development database runs `manage.py migrate silk` once;
the frontend specs need Node 20.19 or later.
