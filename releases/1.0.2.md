# ManuSpectrum 1.0.2 release notes

ManuSpectrum 1.0.2 is a patch release: a security update of the image, fixes found since the opening of the site,
and dependency updates. The data package changes for one widget (manuspectrum-pkg#12); the graphs keep their
publication, so existing resources stay editable.

## Security

- **oauthlib 4.0.1** (CVE-2026-49272, high): a transitive dependency of django-oauth-toolkit, found by the weekly
  scan of the production image.
- **No HTML page under `/static/`**: the npm packages ship sample, test and documentation pages, among them CKEditor 4
  samples with a known cross-site scripting flaw. The image publishes no `.html` or `.htm` static file, and its build
  fails if one gets through. Nothing the site loads is such a file.

## Fixes

- Account activation and password reset links clicked from a webmail no longer end on « invalid link »: a valid link
  opens a « Continue » page instead of a redirect that lost the session cookie.
- The core map popup of a Place shows its text without HTML markup.
- The home page logo uses Cormorant Garamond on every system (it fell back to Georgia on Windows and macOS).
- File-list uploads with several files in one card (arches-vue-components 2.0.3, aligned with the Python package).
- Under `/fr/`, the data-entry cards show their French names, help texts and widget labels again. Arches 8.1.5 writes
  the active language's texts into every language of a graph publication during `i18n synclanguages`, `load_package`
  and « Update published graphs »; the new command `republish_graph_translations` rewrites them from the graph tables,
  in the same publication, and `init` runs it.
- The Component field « Iconographic representation » uses the Biblissima concept autocomplete instead of a plain URL
  field. Existing values are kept.

## Deployment kit

- Grafana's memory limit is 1536 MB in production (constant disk reads at the former limit).
- Ansible verify mode accepts the SSH rate limit as `ufw status verbose` prints it for the `OpenSSH` profile.
- New guides: `deploy/DEPLOY.md` (rebuild from zero, rollback, annual maintenance) and `deploy/INCIDENT.md`
  (decision tree); corrections from the first installation in `ADMIN.md`, `RELEASES.md` and `OBSERVABILITY.md`.

## Dependencies

papaparse 5.7.0, plotly.js-cartesian-dist 4.1.2, @primeuix/themes 3.1.0 (public theme only; Arches keeps its own
copy), primelocale 2.6.2, es-toolkit 1.53.0.

## Upgrading

- Ansible first: a file it installs changed (`roles/baseline/tasks/verify.yml`), so the update refuses until the
  playbook has run from a laptop checkout at `v1.0.2`. Then check that `sudo manuspectrum-update --status` shows
  `needs_ansible=0`.
- Then install the release with `sudo manuspectrum-update` (`deploy/ADMIN.md`, « Updating the application »).
- Then, once, on the host (the service account, from the checkout), update the graphs in place. No new graph
  publication is created; the pre-update backup covers these steps.
  1. Give « Iconographic representation » its widget (`1 row(s) updated`; `0` when it is already done):
     ```bash
     make -C deploy manage ARGS='shell -c "import json; from django.db import connection; c = connection.cursor(); c.execute(\"UPDATE cards_x_nodes_x_widgets SET widgetid = %s, config = %s::jsonb WHERE id = %s AND widgetid = %s\", [\"29905551-a4a5-428c-bf82-2eb0ec464bab\", json.dumps(dict(entityType=\"descriptor\", label=\"Concept URI\", link_color=\"#0055a0\", placeholder=\"\")), \"3d45f30e-7792-4571-af07-497f48d9746b\", \"ca0c43ff-af73-4349-bafd-53ff9f22eebd\"]); print(c.rowcount, \"row(s) updated\")"'
     ```
  2. Rewrite every language of the current graph publications from the graph tables. It names each graph it skips
     because it has unpublished changes: publish those from the Graph Designer, then run this command again.
     ```bash
     make -C deploy manage ARGS="republish_graph_translations"
     ```
  3. Check that every resource is still on its graph's publication (expected: `0 resource(s) off their graph
     publication`):
     ```bash
     make -C deploy manage ARGS='shell -c "from django.db import connection; c = connection.cursor(); c.execute(\"SELECT count(*) FROM resource_instances r JOIN graphs g ON g.graphid = r.graphid WHERE r.graphpublicationid IS DISTINCT FROM g.publicationid\"); print(c.fetchone()[0], \"resource(s) off their graph publication\")"'
     ```
  4. In the browser: `/fr/add-resource/60c85aba-f079-45bc-997f-21cdd4f77b6d` (Analysis) shows « Nom de l'analyse »,
     and an existing Component opens in the editor with the Biblissima autocomplete in « Iconographic
     representation ».
- Run `republish_graph_translations` again after any later `i18n synclanguages` or « Update published graphs » in the
  Graph Designer.
